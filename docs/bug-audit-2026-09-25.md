## 共性问题与实现

### 配置必须区分宿主机地址和容器地址

| 服务 | 宿主机默认 | Compose 内部 | 凭据 / 开关 |
| --- | --- | --- | --- |
| MySQL | localhost:3307 | mysql:3306 | MYSQL_DATABASE、MYSQL_APP_USERNAME、MYSQL_APP_PASSWORD |
| Redis | localhost:6380 | redis:6379 | REDIS_PASSWORD |
| MinIO | localhost:9000 | minio:9000 | MINIO_APP_ACCESS_KEY、MINIO_APP_SECRET_KEY、MINIO_APP_BUCKET 自动映射 |
| Milvus | localhost:19530 | milvus:19530 | SEFORGE_VECTOR_STORE_ENABLED；MILVUS_ENABLED 仅为旧配置 fallback |

`MINIO_HOST_PORT` / `MILVUS_HOST_PORT` 可以避开本机端口冲突。外部存储可显式覆盖 MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY/BUCKET、MILVUS_HOST/PORT；使用随附服务时不要填写 Docker DNS 名称到宿主机配置。

生产 overlay 移除 MySQL、Redis、MinIO、Milvus 宿主机端口，并保留内部 data 网络。未为测试关闭 CSRF/RBAC，未清理数据库或 volume。dev 使用本机 HTTP Cookie，prod 的 Secure Cookie 保持不变。

MinIO Client 改为按需初始化：没有凭据时核心应用可启动，实际存储请求返回可诊断 503。修改 `.env` 不等于轮换持久化服务里的旧账号密码；已有部署要同步轮换，不能通过删除 volume 解决。

### 错误跨 API / SSE / 页面完整传递

- 普通 API：保留 HTTP 状态、业务错误码、字段 details 和 traceId；页面显示字段级校验或服务诊断。
- Course QA：检索失败不启动回答模型，不持久化半条 assistant；SSE error 保留存储错误码，页面显示错误及重试入口。
- Sonar：仅将固定配置错误映射为 `SONAR_TOKEN_MISSING`、`SONAR_SCANNER_MISSING`、`SONAR_URL_INVALID`、`SONAR_DISABLED`；其他扫描错误仍为安全的 `SONAR_FAILED`，不回显 Token、命令行或供应商响应体。
- 未知异常只记录类型和有限调用位置，不记录完整 Prompt、答案、密码或 Session。

### 额外回归发现

- Analytics 同课程并发刷新：`INSERT IGNORE` 遇到已有主键时的共享锁，再升级 `FOR UPDATE`，可造成双方锁升级死锁。改为直接取得排他行锁的 upsert，保留原增量算法。
- Phase 4 截止时间测试：直接通过 JdbcTemplate 写 Timestamp 使用 Windows 本地时区，而 Hibernate 按 UTC 读写，导致“已经截止”的测试数据实际上晚了 8 小时。夹具改用 MySQL UTC_TIMESTAMP；未放宽提交规则。
- Phase 3 删除测试：原先断言 IOException，现应断言明确的 `STORAGE_UNAVAILABLE / OBJECT_NOT_FOUND`，继续验证删除后的对象确实不存在。
- Sonar 集成夹具：将 Windows `C:\...` 工作目录直接传给 Linux scanner，导致 `Project home must be an existing directory`。测试桥接层改为受控 `/tmp/seforge-sonar-*` 路径映射，清理也只针对该目录；未修改生产 scanner 权限或网络边界。
- 错误 HTTP 方法被全局兜底异常处理器转成 500：审计脚本一度对仅支持写入的 `/admin/semesters` 执行 GET，日志确认 HttpRequestMethodNotSupportedException。读取路由应为 `/semesters`；同时修复通用异常映射，错误方法返回 405 + Allow，缺少参数/参数类型错误返回 400，而不是伪装为服务故障。此发现不等于 BUG-3 已确认同根因。

## 本地复现与重启

从根目录启动基础设施：

```powershell
docker compose --env-file .env -f backend/docker/docker-compose.yml up -d mysql redis minio minio-init etcd milvus
```

从 backend 启动 API 与另一个终端的 worker：

```powershell
.\mvnw.cmd spring-boot:run
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.profiles=dev,worker'
```

它们是两个终端分别执行的命令，不要在同一个前台进程里等待第二条启动。原有 8080 API 未被本轮强制终止，需用户重启后加载最新代码；Vite 可热更新前端。V10 已在本地真实数据库执行成功，历史 V1～9 不变。

可重复的合成数据 smoke 脚本（会创建测试账号/课程/作业、调用已配置的真实模型并产生费用；不使用真实学生内容）：

```powershell
# backend 目录；指向正在运行的 API，确保另有 worker。
$env:AUDIT_BASE='http://localhost:8080'
$env:AUDIT_AI='true'
node scripts/verify-local-ai.mjs
```

脚本只在内存中使用账号凭据，结果写入 ignored target。退出码 1 表示断言/请求失败，2 表示 Code Review 未完成，不能把其输出当成全链路 PASS。需已有本地 Bootstrap 管理员配置；不要对生产环境运行。脚本本身不会创建或配置 Sonar Token。

## 保留的限制

1. BUG-3 原始 500 尚未定位到具体异常，需要原 traceId/日志或可复现数据；本轮不得写成“确认由 MinIO 导致”。
2. Code Review 真实扫描与其后 Code Review Agent 未通过：须按运维文档配置 SonarQube、受限分析 Token 与隔离 scanner，再重试。不能在未扫描时使用 LLM 伪造 finding。
3. DeepSeek 未配置，真实供应商断流/429/超时等全组合没有逐一注入；单测覆盖不等于真实供应商覆盖。
   Tutor 的真实业务操作覆盖 Hint 与提交前 FullSolution 拒绝；Document Review 的真实输入为 SRS，未对六种 Tutor 操作及每种文档类型逐一计费调用。其他操作的源码接入及自动化回归不冒充真实供应商逐项验收。
4. 本轮合成 PDF smoke 不重新宣称全部文档格式及语义 Golden Set 的真实模型指标达标。
5. Windows 工具启动的 JDK 出现 Unix-domain socket Invalid argument。测试进程使用 `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:/seforge-uds-unavailable` 强制内部管道回退 TCP；没有写入运行配置或改变生产网络策略。
6. 合成 audit 账号/课程/作业仍保留以便追踪，未删除用户数据或测试记录；临时验证 JVM 已停止，基础设施保留运行。

本轮没有自动 commit/push。Engineering Verification 不等于 User Acceptance；需要用户在重启后的实际页面进行验收。
